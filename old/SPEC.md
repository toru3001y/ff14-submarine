# FF14潜水艦パーツ組み合わせ計算ツール 仕様書

作成日: 2026-08-08
バージョン: v1.0（リファクタリング前・現行仕様の記録）

---

## 1. 概要

FF14（Final Fantasy XIV）の潜水艦システムにおいて、パーツ（艦体・艦尾・艦首・艦橋）と
潜水艦ランクの組み合わせから、最終的なステータス値（探査・収集・巡航・航続・運）および
コスト・キャパシティを計算するツール。

- 形式: 単一HTMLファイル（HTML/CSS/JavaScript、ビルド不要）
- 外部依存: SheetJS (xlsx.full.min.js) をCDN経由で読み込み（Excelエクスポート用）
- 想定利用者: FF14プレイヤー本人（開発者本人）

## 2. 機能要件

### 2.1 潜水艦ランク選択機能

| 項目 | 内容 |
|---|---|
| 入力方式 | 数値入力フィールド（`<input type="number">`） |
| 範囲 | 1〜135 |
| 操作方法 | キーボード直接入力 + ブラウザ標準のスピンボタン（上下矢印） |
| バリデーション | 範囲外の値が入力された場合、赤字で「ランクは1～135の範囲で入力してください」と表示 |
| ボーナス表示 | 選択ランクに応じて「キャパシティ、探査、収集、巡航、航続、運」のボーナス値をリアルタイム表示 |
| 未入力時の表示 | 「ランクボーナス: キャパシティ0, 探査+0, 収集+0, 巡航+0, 航続+0, 運+0」 |

### 2.2 パーツ選択機能（艦体・艦尾・艦首・艦橋）

| 項目 | 内容 |
|---|---|
| 部位数 | 4部位（艦体、艦尾、艦首、艦橋） |
| 選択方式 | `<select>` プルダウン、部位ごとに独立 |
| パーツ数 | 各部位10種類（5系統 × 通常/改級） |
| 表示順序 | 系統ごとにグループ化。系統内は「通常級→改級」の順<br>系統順: シャーク級→ウンキウ級→ホエール級→シーラカンス級→シルドラ級 |
| プルダウン表示形式 | `{パーツ名} (コスト{コスト値})` 例: `シャーク級艦体 (コスト5)` |
| 選択時の性能表示 | プルダウン下部に「パーツ性能: コスト{X}, 探査{±X}, 収集{±X}, 巡航{±X}, 航続{±X}, 運{±X}」を表示 |
| 未選択時の性能表示 | 「パーツ性能: コスト0, 探査+0, 収集+0, 巡航+0, 航続+0, 運+0」 |

### 2.3 総合ステータス計算・表示機能

| 項目 | 内容 |
|---|---|
| 計算式 | 総合値 = Σ(4部位のパーツ性能値) + ランクボーナス値（コストのみランクボーナス対象外） |
| 表示項目 | コスト、探査、収集、巡航、航続、運の6項目 |
| コスト表示形式 | `{現在コスト} / {キャパシティ}`（キャパシティ情報を併記） |
| 色分け | 正の値=緑、負の値=赤、コストは通常時黒 |
| 選択中パーツ一覧表示 | 4部位それぞれの選択中パーツ名を別枠で表示（未選択時「未選択」） |

### 2.4 キャパシティ超過チェック機能

| 項目 | 内容 |
|---|---|
| チェック条件 | 選択中パーツのコスト合計 > 選択ランクのキャパシティ |
| 超過時の表示 | 画面上部に赤背景のエラーバナー「⚠️ コストがキャパシティを超過しています！キャパシティ内に収まるパーツを選択してください。」 |
| 超過時の追加演出 | コスト数値・キャパシティ情報表示を赤色化し、パルスアニメーション（1.5秒周期の明滅） |
| チェックタイミング | パーツ選択変更時、ランク変更時にリアルタイム再計算 |

### 2.5 Excelエクスポート機能

| 項目 | 内容 |
|---|---|
| トリガー | 「📥 Excelファイルをダウンロード」ボタン |
| 出力形式 | .xlsx（SheetJSライブラリ使用） |
| ファイル名 | `FF14潜水艦構成_{YYYY-MM-DD}.xlsx`（当日日付） |
| シート1: 選択された構成 | ランク情報＋4部位の選択パーツ＋合計行（部位/パーツ名/コスト/探査/収集/巡航/航続/運の列） |
| シート2: 全パーツ一覧 | 40パーツ全件のマスタデータ |
| シート3: ランクボーナス一覧 | ランク1〜135の全ボーナス・キャパシティデータ |

### 2.6 リセット機能

| 項目 | 内容 |
|---|---|
| トリガー | 「🔄 選択をリセット」ボタン |
| 動作 | ランク入力・4部位の選択・全表示・エラー状態をすべて初期状態に戻す |

## 3. データ仕様

### 3.1 パーツデータ（partsData）

構造: 部位名をキーとするオブジェクト、各値はパーツ配列（10件）

フィールド対応:
| フィールド名 | 意味 |
|---|---|
| name | パーツ名（例: シャーク級艦体） |
| cost | パーツコスト（通常級は5/9/12/14/17、改級は全て20で統一） |
| exploration | 探査値（マイナスあり） |
| harvest | 収集値（マイナスあり） |
| surveillance | 巡航値（マイナスあり） |
| range | 航続値（マイナスあり） |
| favor | 運値（マイナスあり） |

系統別コスト一覧（通常級）:
| 系統 | コスト |
|---|---|
| シャーク級 | 5 |
| ウンキウ級 | 9 |
| ホエール級 | 12 |
| シーラカンス級 | 14 |
| シルドラ級 | 17 |
| （全）改級 | 20 |

※ 実データはPart 4を参照

### 3.2 ランクボーナスデータ（rankBonusData）

構造: ランクごとのオブジェクトの配列（ランク1〜135、135件）

傾向:
- ランク1〜49: ステータスボーナス全て0、キャパシティは20から1ずつ増加（ランク1=20 → ランク49=68）
- ランク50〜135: キャパシティ80で固定
- ランク51〜135: 探査・収集・巡航・航続・運のボーナスが段階的に増加（ランク135で最大値: 探査100/収集130/巡航90/航続120/運95）

※ 実データはPart 5を参照

### 4.3 タイポグラフィ・スタイル詳細

- フォント: `'Segoe UI', Tahoma, Geneva, Verdana, sans-serif`
- コンテナ: 最大幅1200px、中央寄せ、角丸10px、box-shadow付き
- 見出し(h1): 中央揃え、下線3px実線
- パーツグループ: 角丸8px、枠線2px、パディング20px
- 入力欄フォーカス時: 青枠 + 薄い青のbox-shadow（フォーカスリング風）
- ステータス数値: 24pxボールド
- キャパシティ超過時: 該当数値に赤字+パルスアニメーション（1.5秒、opacity 0.7↔1.0）
- ボタン: 角丸6px、パディング12px 25px、ホバー時にtranslateY(-2px)で浮き上がる演出

### 4.4 レスポンシブ対応

- パーツ選択グリッド: `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))`
  → 画面幅に応じて1〜4列に自動調整
- ステータスグリッド: `repeat(auto-fit, minmax(120px, 1fr))`
- 選択中パーツ表示: `repeat(auto-fit, minmax(200px, 1fr))`

### 4.5 UI上の既知の課題（リファクタリング時の検討ポイント）

- ランク入力欄がプルダウン式パーツ選択とビジュアルトーンが異なる（数値入力 vs セレクトボックス）
- パーツ性能・ランクボーナスのテキスト表示が長い一行文字列になっており、視認性に改善余地あり
- キャパシティ超過エラーは目立つが、超過していない場合の「余裕度」が視覚的にわかりにくい
- 6項目の総合ステータスが横並びグリッドのみで、優先度や関連性の表現がない
- モバイル表示時の最適化は未検証（グリッドのauto-fitに依存した簡易対応のみ）

## 5. 非機能要件・技術的制約

- ブラウザのみで完結（サーバーサイド処理なし、ローカルストレージ不使用）
- 外部ライブラリはCDN経由のSheetJSのみ
- 単一HTMLファイルとして配布・利用可能な構成を維持すること（リファクタリング後も推奨）

---

## 6. 既知のデータ上の注意点

- 元データファイル: `ff14潜水艦_パーツ性能.xlsx`、`ランクボーナス.xlsx`
  （これらのソースファイルは本ツールには同梱されていないため、値の再確認が必要な場合は
  再アップロードが必要）
- キャパシティ項目は「値の取り込みのみ」の対応段階であり、将来的な追加要件が
  ユーザーから提示される可能性がある（詳細未定）

## 7. リファクタリング・UI変更にあたっての申し送り事項

1. **機能仕様（本書2章・3章）は現状維持を前提**とし、UI（本書4章）のみ変更する想定
2. データ構造（partsData, rankBonusData）は他の計算ロジックと密結合しているため、
   フィールド名・型を変更する場合は全参照箇所の洗い出しが必要
3. Excelエクスポートの列名・シート構成は運用上の実績があるため、変更する場合は
   利用者（開発者本人）に事前確認を取ること
4. 開発時の変更管理はGitを用い、小さくコミットを積むこと
